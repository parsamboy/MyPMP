# گزارش بررسی و انتخاب سورس

## فایل‌های مرجع

هر دو فایل از commit `110bd14eac6c11747f7d6f02ca20859e3a4e4c64` مخزن `parsamboy/tseOption` دریافت و بررسی شدند:

1. `tseOption_ExoticFilter_v0.0.4.6.source.js` — ۲٬۴۱۸ خط / ۱۵۷٬۹۲۳ بایت.
2. `tseOption_ExoticFilter_v0.0.4.d.source.js` — ۱٬۴۳۱ خط / ۹۴٬۰۱۱ بایت؛ سربرگ خود فایل آن را `v0.0.4.7.min` و SUMMARY-only معرفی می‌کند.

هر دو فایل در محیط Node با `node --check` معتبر بودند.

## تفاوت مهم

فایل دوم فقط فشرده‌سازی متن نیست: حدود ۹۸۷ خط کمتر دارد و حالت Verbose/بخش‌هایی از Debug و آزمون‌های داخلی، بخشی از APIها و گروهی از گزینه‌ها/منطق‌های نسخهٔ کامل را حذف یا ساده می‌کند. در میان موارد قابل‌مشاهده در مقایسهٔ تنظیمات: position sizing، backtest، بخشی از تنظیمات منحنی نرخ بدون ریسک/تقویم سود تقسیمی، ADX و ورود/گردکردن/پنجرهٔ اگزوتیک. چند بخش UI و hook نیز جمع‌وجور یا حذف شده‌اند. بنابراین جایگزینی کامل 0.0.4.6 با فایل d، برای الزام «حفظ ساختار و منطق کاربر» انتخاب مطمئنی نیست.

## مبنای انتخاب

نسخهٔ کامل 0.0.4.6 به‌عنوان مبنای رفتار انتخاب شد. هدف این نسخهٔ جدید «کم‌کردن بایت‌ها با حذف قابلیت» نبوده است. از فایل d فقط الگوی خروجی SUMMARY-only به‌عنوان قرارداد انتشار بررسی شد؛ چون خروجی وب/TSETMC این پروژه هر دو حالت کامل را ارائه می‌دهند، کد منبع را بی‌دلیل به SUMMARY-only محدود نکردیم.

## اصلاحات محدود پروژهٔ جدید

- نام محصول به `tseOptionZharfa` و زیرعنوان دقیق به `tseOptionAbyss -v0.0.1` تغییر کرد؛ منشأ، نویسنده، تماس و مجوز اصلی در سربرگ باقی است.
- تنظیم‌های کاربر هنگام ساخت Context مؤثر می‌شوند؛ در نسخهٔ پایه Context مستقیماً `CONFIG` را می‌گرفت و بعضی overrideهای ذخیره‌شده در فیلترهای متکی به `ctx.cfg` اثر نمی‌کردند.
- آزمون داخلی، پس از تست cache، مقدار قبلی `baseInsCodes` کاربر را دقیقاً بازمی‌گرداند؛ قبلاً آن را با `{}` جایگزین می‌کرد.
- fallbackهای قیمت/مظنه/نوسان و IV Rank در نتیجه به‌عنوان هشدار داده‌ای مشخص می‌شوند، بدون تغییر آستانه‌های مالی پایه.
- نمونهٔ تصادفی فقط در فرمان صریح TSETMC و پس از `confirm`، با برچسب SIMULATION اجرا می‌شود؛ در وب‌اپ مستقل مسدود است.
- جداکنندهٔ query در URLهای نمونه با `String.fromCharCode(38)` ساخته شده تا قرارداد ثبت رعایت شود.

## مواردی که عمداً بازطراحی نشدند

- فرمول‌ها، آستانه‌های پیش‌فرض، وزن‌ها، سررسیدها و سیاست‌های مالی از نو کالیبره نشده‌اند.
- استخراج snapshot زندهٔ همهٔ نمادهای TSETMC پیاده‌سازی/ادعا نشده است؛ وب‌اپ از JSON کاربر استفاده می‌کند و API موتور برای اتصال معتبر آینده در دسترس است.
- مقدار fallbackهای عددی قدیمی برای حفظ رفتار مبنا حذف نشده؛ در عوض در خروجی هشدار داده می‌شود. برای تصمیم واقعی، تاریخچه و مظنهٔ معتبر را کنترل کنید.

## اجرای شش اقدام و تصمیم‌های حفاظتی

- تبدیل تاریخ به یک مبنای JDN یکپارچه شد؛ امروز بازار با timezone تهران محاسبه می‌شود و pool/IV history قدیمیِ دارای Unix-day ordinal در مرز بارگذاری migrate می‌شود.
- `TSE_CALENDAR` شنبه تا چهارشنبه را روز معاملاتی می‌گیرد، تعطیلات قابل‌ورود دارد و پوشش تعطیلات را فقط با اعلام صریح سال کامل می‌داند. نبود دادهٔ تعطیلات به‌عنوان «تقویم کامل» فرض نمی‌شود.
- DTE تقویمی و معاملاتی جدا هستند. پیش‌فرض `modelTimeBasis: legacy-hold` و `volatilityAnnualizationMode: legacy252` حفظ شد؛ `calendar-expiry` و `tse-trading` انتخاب‌های آزمایشی‌اند و theta از روزهای سالانهٔ مدل مطلع می‌شود.
- لایهٔ L8 پس از L7 به‌عنوان گزارش اطلاعاتی افزوده شد. این لایه فقط برای نمادهای عبوری سناریوهای تغییر قیمت نظری را محاسبه می‌کند؛ هیچ‌گاه نمادی را حذف یا رتبه‌بندی نمی‌کند. سناریوها فرض ثابت بودن IV/rates/dividends، هزینهٔ معاملهٔ صفر و یک مبنای سررسید مشخص را افشا می‌کنند.
- مسیر pool دیگر از اندیس ردیف‌ها تاریخ نمی‌سازد، حجم/تعداد معاملهٔ ثابت جعل نمی‌کند و قیمت تنظیمی یا مقدار مدل‌شده را observation تاریخی نمی‌نویسد. برای تاریخچه، تاریخ و قیمت هر ردیف باید قابل‌استخراج باشد؛ برای قیمت زنده، cache باید تازه باشد. ردیف‌های legacy فاقد provenance هنگام بارگذاری از مبنای spot، realized volatility، میانگین حجم/تعداد و IV Rank کنار گذاشته می‌شوند؛ تاریخچه حفظ می‌شود اما معتبر فرض نمی‌شود.
- وب‌اپ مستقل ورودی تقویم، سال کامل، مبنای زمان و افق/شوک‌های سناریو دارد؛ خروجی JSON و CSV نیز وضعیت advisory را منعکس می‌کنند. هیچ تقویم تعطیلاتی خودکار دانلود نمی‌شود.

## آزمون‌های این پروژه

`npm run check` علاوه‌بر `node --check`، نام/نسخه و انتساب، قرارداد بدون HTML entity، هشت لایه و ترتیبشان، اعمال override، عدم اجرای خودکار شبیه‌سازی، fallbackهای هشدارخورده، مرجع‌های تبدیل JDN/جلالی، تقویم ناقص/کامل، مبناهای زمان، پارسر تاریخ واقعی، مهاجرت pool، سالانه‌سازی بدون fallback جعلی، رفتار theta و غیرحذفی‌بودن L8 را کنترل می‌کند. آزمون مرورگر دستی نیز با `web/` قابل انجام است.

## مرزهای شناخته‌شده

فهرست تعطیلات رسمی باید از سوی کاربر/منبع معتبر تکمیل و صحت آن جداگانه بررسی شود؛ صرف انتخاب یک سال به‌عنوان کامل، مسئولیت صحت آن داده را به اپ منتقل نمی‌کند. سناریوهای نگهداری فعلی بر مبنای قیمت نظری Black–Scholes با سررسید تقویمی‌اند و هزینه/لغزش، تغییر IV، سود تقسیمی و نقدشوندگی آینده را پیش‌بینی نمی‌کنند. منابع قدیمی pool که provenance نداشته‌اند «قابل‌تأیید» فرض نمی‌شوند.

## تکمیل فازهای قرارداد، advisory و build

- وضعیت تقویم در API و L8 صریح است؛ DTE معاملاتی فقط با سال/سال‌های کاملِ صریح عدد می‌شود وگرنه unknown می‌ماند. نمودار theta صرفاً برآورد نظری با پایه/IV/نرخ ثابت است و هشدار تعطیلات پیوسته فقط با پوشش کافی روشن می‌شود.
- Trend از سری شاخص fresh/مرتب، صرفاً برچسب توصیفی می‌دهد؛ پیش‌فرض unknown، بدون score یا اثر فیلتر. Profile مستقل وب فقط تنظیمات فعال را نمایش می‌دهد و هیچ threshold را تغییر نمی‌دهد. فرم تنظیمات هر دو رابط برای تغییر، diff قدیم → جدید و تأیید دارد.
- pool/IV در envelope اتمیک schema v2 ذخیره می‌شوند؛ migration backup می‌سازد، schema آینده را overwrite نمی‌کند و writerهای عملیاتی از guard واحد identity/version/source/freshness عبور می‌کنند.
- پاسخ خام endpoint زندهٔ TSETMC تأیید نشده است. قرارداد adapter نسخهٔ ۱ و fixtureهای normalized اضافه شده‌اند؛ این fixtureها ادعای دادهٔ خام بازار نیستند و تا ثبت adapter معتبر، parser حدس عددی نمی‌زند.
- `src/manifest.json` ترتیب ده قطعهٔ closure کلاسیک را تعیین می‌کند؛ `scripts/build.js` فقط concat قطعی انجام می‌دهد (بدون minify) و `npm run check` parity بایت‌به‌بایت را همراه ۲۹ تست بررسی می‌کند.
