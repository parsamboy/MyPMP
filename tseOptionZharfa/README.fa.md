# tseOptionZharfa — `tseOptionAbyss -v0.0.1`

نسخهٔ مستقل و قابل ثبت در TSETMC از قیف چندلایهٔ اختیارها. این انشعاب از سورس کامل `tseOption_ExoticFilter_v0.0.4.6.source.js` ساخته شده؛ نسخهٔ SUMMARY-only فقط برای مقایسه و انتخاب بهینه‌سازی‌های بی‌تغییرِ رفتار استفاده شد.

## دو روش استفاده

### ۱) برنامهٔ وب مستقل

وب‌اپ، دادهٔ بازار را خودش دریافت نمی‌کند و هیچ ردیف ساختگی را خودکار نمی‌سازد. آرایهٔ JSON واقعی را در کادر وارد کنید یا فایل JSON انتخاب کنید؛ پردازش در همان مرورگر انجام می‌شود و داده به سرور ارسال نمی‌شود.

برای اجرا از ریشهٔ این پوشه:

```bash
python3 preview_server.py
```

سپس `http://localhost:4173/` را باز کنید؛ ریشه به `/web/` هدایت می‌شود. برای تغییر درگاه می‌توانید `PORT=4174 python3 preview_server.py` اجرا کنید. فایل‌ها محلی و بدون وابستگی npm هستند. برای استفادهٔ واقعی، فیلدهای منبع داده را مطابق قرارداد موتور تأمین کنید. الگوی ورودی و نام فیلدها در placeholder صفحه آمده است.

### ۲) اسکریپت TSETMC

فایل [`tseOptionZharfa.js`](./tseOptionZharfa.js) را به‌صورت JavaScript خام در محیط ثبت/اجرای موردنظر وارد کنید؛ آن را داخل HTML قرار ندهید و HTML entityها را روی سورس اجرا نکنید. نسخهٔ فعلی همان سورس کامل و دارای هر دو حالت Summary/Verbose است؛ minifier روی آن اجرا نشده است. کد توسعه در `src/` به قطعه‌های کلاسیکِ یک closure تقسیم شده و build آن‌ها را با ترتیب ثابت کنار هم می‌گذارد تا قرارداد ثبت TSETMC و ترتیب اجرا حفظ شود.

دکمهٔ داخل پنل با عنوان «اجرای شبیه‌سازی» فقط پس از پیام هشدار و تأیید کاربر دادهٔ تصادفی می‌سازد. این خروجی **دادهٔ بازار نیست**. برای ورودی واقعی از API موتور (`window.__exf.run(rows)`) استفاده کنید؛ این نسخه از خودش ادعا نمی‌کند که snapshot نمادهای TSETMC را استخراج کرده است.

**قرارداد adapter زنده:** قالب پاسخ خام endpoint در محیط قابل‌تأیید نبود؛ بنابراین parser عمداً regex عددی را به‌کار نمی‌برد و پاسخ خام تا زمان ثبت adapter نسخهٔ ۱ رد می‌شود. adapter باید شناسه، last price، timestamp/freshness و فیلدهای تاریخچه را به schema canonical تبدیل کند؛ fixtureهای پوشهٔ `fixtures/` فقط قرارداد normalized را تست می‌کنند. جزئیات: [`docs/adapter-contract.fa.md`](./docs/adapter-contract.fa.md).

## تقویم، مبنای زمان و سناریوها

- تاریخ‌ها در مرز ورودی به JDN یکپارچه می‌شوند؛ ورودی JDN، `YYYYMMDD` جلالی/میلادی، تاریخ جداشده، و ordinal قدیمی Unix-day پشتیبانی می‌شود. داده‌های pool قبلی نیز هنگام بارگذاری migrate می‌شوند.
- تقویم TSE روزهای شنبه تا چهارشنبه را معاملاتی می‌داند. تعطیلات رسمی از تنظیم کاربر می‌آیند؛ هیچ منبع تعطیلاتی خودکار دریافت نمی‌شود. سال فقط وقتی «کامل» است که کاربر پوشش کاملش را صریحاً در `marketCalendarCompleteYears` اعلام کند.
- پیش‌فرض‌های مدل زمانی `legacy-hold` و سالانه‌سازی `legacy252` هستند و بدون انتخاب صریح عوض نمی‌شوند. گزینه‌های `calendar-expiry` و `tse-trading` آزمایشی‌اند؛ حالت معاملاتی در نبود پوشش کامل تقویم فعال نمی‌شود. DTE تقویمی و معاملاتی جدا نگه داشته شده‌اند.
- لایهٔ هشتم فقط **advisory** است: سناریوی نظری اختیار و chart زوال تتا را برای افق نگهداری محاسبه می‌کند؛ فیلتر، رتبه، TP/SL یا توصیهٔ ورود/خروج نمی‌سازد. DTE تقویمی و معاملاتی جداست؛ DTE معاملاتی در تقویم ناقص `unknown` می‌ماند. تعطیلی پیوسته فقط با تقویم کامل هشدار قطعی می‌گیرد و فرض ثابت‌بودن IV/نرخ/سود تقسیمی همراه برچسب «برآورد نظری» نمایش داده می‌شود.
- تاریخچه فقط با تاریخ و قیمت قابل‌خواندن از ردیف تاریخچه یا مشاهدهٔ زندهٔ تازه به pool افزوده می‌شود. اندیس ردیف به «امروز منهای n روز» تبدیل نمی‌شود؛ قیمت تنظیمی/فرضی یا قیمت مدل‌شده نیز به‌عنوان observation تاریخچه ثبت نمی‌شود. ردیف‌های قدیمی pool که منشأ ندارند برای قیمت/نوسان/حجم/IV Rank معتبر شمرده نمی‌شوند و نمودار آن‌ها را به‌عنوان بازار واقعی نمایش نمی‌دهد.

در TSETMC، تقویم تعطیلات و سال‌های کامل را با دقت و از منبع معتبر تنظیم کنید. در وب‌اپ مستقل، همین گزینه‌ها پس از تأیید ثبت می‌شوند. تا وقتی داده یا فرض معتبر در دسترس نیست، سناریوها باید با وضعیت/هشدار ناکافی دیده شوند؛ پیش‌فرض مالی اصلی برای حفظ سازگاری همچنان legacy است.

## اصولی که ثابت مانده‌اند

- هفت لایهٔ اصلی، registry/schema، تنظیمات و حالت‌های نمایش نسخهٔ کامل حفظ شده‌اند؛ لایهٔ هشتم افزوده‌شده صرفاً اطلاعاتی است.
- پیش‌فرض‌های مالی، وزن‌ها و آستانه‌ها از سورس کامل نگه داشته شده‌اند؛ تغییر آستانه در وب‌اپ نیاز به تأیید صریح دارد.
- ورودی واقعی وب‌اپ پیش از اجرا clone می‌شود تا موتور، فایل/متن اصلی کاربر را تغییر ندهد.
- نبود یا کهنگی تاریخچه/مظنه در مسیرهای fallback به‌صورت هشدار در خروجی منعکس می‌شود؛ این هشدار جایگزین بررسی کیفیت داده نیست.
- تنظیمات ذخیره‌شده در `localStorage` برای سازگاری با namespace نسخهٔ پایه حفظ می‌شوند.
- انتساب مؤلف اصلی، نشانی‌ها، مجوز `Smart-FFA-1.0` و رفع مسئولیت حذف نشده‌اند.

## آزمون و بررسی

```bash
npm run build   # بازسازی قطعی artifact از src/
npm run check   # node --check + parity بایت‌به‌بایت + آزمون‌ها
```

این فرمان `node --check` سورس TSETMC و آزمون‌های رگرسیون/تقویم/adapter/storage/pool/مدل/تاریخچه/سناریو را اجرا می‌کند. `npm run check` شکست می‌خورد اگر artifact با concat قطعه‌های `src/` متفاوت باشد. یادداشت مقایسهٔ دو فایل ورودی: [`docs/code-review.fa.md`](./docs/code-review.fa.md). چک‌لیست قرارداد TSETMC: [`docs/tsetmc-contract.fa.md`](./docs/tsetmc-contract.fa.md).
